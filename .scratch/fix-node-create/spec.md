# 修好节点创建

Status: ready-for-agent

## Problem Statement

节点创建这条路径上有五处真问题，从「谁能建」一直坏到「建完页面上显示什么」。

**建节点没有任何角色判定。** 两侧收敛那一轮扫过了套餐、账号、链路组，节点被漏了。
AddNode 里专门有一条给非管理员走的分支：普通用户建完节点，顺手往
`user_role_node_mappings` 里给自己写一行——自己给自己发资源授权，而这正是
CLAUDE.md 里说只能由管理端在「转发用户 › 资源授权」里做的那件事。用户端没有这个
界面，但接口就在那儿，一条手写请求的距离。

**插完立刻按 key 回查，且丢掉了回查的错误。** 紧接着解引用查回来的行。回查一失败
就是 nil 解引用，整个请求 panic，而不是返回一个分类过的错误。这次回查本身也是多余
的——插入已经把自增 id 填回实体了。

**两次写库没有事务。** 先插节点，再插归属行。第二步失败就留下一个没有归属的孤儿
节点，操作者重试便多一个节点、多一个 key。这与「新建账号会报错但已经建好，重试就
多出一个同名账号」是同一个形状，只是换了张表。

**「默认走 IPv6」被收下然后扔掉。** 表单发它、请求结构体绑它、创建从不存它。它只在
创建对话框的内存里活着，交给安装命令那一下。从节点列表里再点开同一个节点的安装命令
时没人传这个值，命令里就没有 `--prefer-ipv6` 了——同一个节点，两个入口给出两条不同
的安装命令。

**状态列里的「8123」是编出来的。** `nodes.status` 的库默认值是字符串 `'8123'`（某次
把端口写进了状态列），而整个后端没有任何一处写过这一列——节点注册时更新的是
ip/port/ipv4/ipv6/manager_ip，不碰状态。于是每个新建的节点在列表里状态永远是
「8123」，页面上「agent 最后写的值原样显示」那句注释是错的，「在线」那条分支不可达。

## Decisions

- **建节点收归管理员。** 加角色判定，删掉非管理员那条自授权分支。资源可见性仍然只
  由资源授权决定。副作用是好的：管理员本来就绕过所有 per-resource 判定，不需要归属
  行，于是创建只剩一次写库——孤儿节点和那次被忽略的回查一起没了，事务也就不必要了。
- **校验规则落在服务层的纯函数里**，不只挂在请求标签上：标签只在 HTTP 绑定时生效，
  而倍率现在连标签都没有。理由与套餐创建那次相同。
- **「默认走 IPv6」加列持久化**，节点列表带回来，安装命令对话框从行里读。
- **状态这次只做到「未注册 / 在线」**。真正的离线判定需要心跳或最后见到时间，仓库里
  一个这样的信号都没有，那是另一件事；但页面不该继续显示一个编造的值。

## Out of Scope

- 节点重名拒绝。节点在下拉里还带着 IP 和类型，比套餐好分辨。
- 离线判定（心跳 / 最后见到时间 / 定期探活）。
- 归属行 `node_id` 是 int 而主键是 bigint unsigned 的截断——要到 21 亿个节点才踩到。
- 存量的按角色码写的归属行：不再新写，但也不清理。
