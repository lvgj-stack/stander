# 02: 节点名与倍率在服务端也被校验

**What to build:** 空名字、只有空格的名字、零或负数的倍率、不认识的节点类型，都会被
当场拒掉，错误里说明是哪个字段不对。名称两端的空格自动去掉，「hk-01」和「hk-01 」
不会变成两个节点。

今天这些只有前端表单拦得住。名称的「必填」只管字段在不在，全是空格照样通过；倍率
连一条校验都没有，零倍率意味着这个节点上的流量永远不计费，负倍率意味着用得越多剩得
越多。规则集中在服务层的一个纯函数里，用表驱动测试盯住边界，而不是挂在请求标签上：
标签只在 HTTP 绑定时生效，规则写两遍必然漂移。

**Blocked by:** 01（创建路径先收成一条，否则每条规则要写两遍）

**Status:** done

- [x] 名称去掉两端空格后为空 → 参数类错误，指明是名称
- [x] 名称两端的空格被裁剪后再落库
- [x] 倍率为 0 或负数 → 参数类错误（现在 0 会静默落成库里的默认值 1，负数会原样存下）
- [x] 节点类型不是入口/出口两者之一 → 参数类错误
- [x] 校验规则只存在一处，表驱动测试覆盖上面每一条以及合法取值（prior art：套餐周期
      那组表驱动用例，与被测代码同包）
- [ ] 前端表单给出的提示与服务端拒绝的理由说的是同一件事

## 收尾说明

最后一条只对**创建**成立，没有打勾。新增/编辑用的是同一个对话框，而 EditNode 至今
不校验：名字不裁空格、倍率为零照收。所以在编辑模式下，表单说的和服务端做的仍然不是
一回事。

那半边是另一件事，已经单独记在 `.scratch/node-edit-validation/issues/01-edit-node-keeps-the-rules.md`
——它牵扯到「零和没传在 float32 上分不开」这个问题，会改到请求结构体和前端，不适合
夹在这张票里做。
