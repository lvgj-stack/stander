# 04: 「默认走 IPv6」被节点记住

**What to build:** 创建节点时勾了「默认走 IPv6」，这个选择跟着节点一起存下来。之后
从节点列表里再打开这个节点的安装命令，拿到的命令和创建那一刻给出的完全一样，同样带
着 `--prefer-ipv6`。

今天这个开关只活在创建对话框的内存里：请求里带着它，但创建从不把它存进节点。于是从
列表打开安装命令时没人知道该不该加这个参数，同一个节点从两个入口能拿到两条不同的
命令，照着后一条装出来的 agent 注册的是 IPv4 地址。

## 收尾说明

做完了，在 `worktree-prefer-ipv6` 分支上（`48590f9`），尚未合回 main。**这条分支包含
票 03**：两者都动 nodes 表和同一个测试辅助函数，分开做必然冲突。

nodes 加了一列 `prefer_ipv6`，创建时写入，列表接口带回来，安装命令对话框按它决定加不加
`--prefer-ipv6`。存量行一律视为没勾——这个选择以前没存过，也无从倒推。

产物按 `docs/development.md` 的三步走重新生成，没有手改。纯粹的重新生成先单独提交了
（`92ee8ed`，顺带补上票 03 欠的那一步），所以功能提交的 diff 里只有这一列自己的东西。

`init.sql` 的列注释和迁移脚本里的一字不差，这点是验过的：拿 `init.sql` 建一个全新的库、
对它跑一次 `stander gen`，产物和用迁移过的库生成的逐字节一致。差一个 `comment` 子句就会
生成出不一样的 tag。

### 最后一条验收标准的实际覆盖
