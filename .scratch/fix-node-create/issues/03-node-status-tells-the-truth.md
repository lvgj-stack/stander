# 03: 新建的节点不再显示「8123」

**What to build:** 刚建好的节点在列表里显示「未注册」；把安装命令在目标机器上执行、
agent 连上控制面之后，同一行变成「在线」。

今天这一列显示的是数据库默认值 `'8123'`——某次把端口写进了状态列——而后端没有任何
一处写过它，所以「在线」那条分支永远不会命中，每个节点从建出来那天起就一直挂着一个

那是另一件事。页面不该暗示它知道得更多。

## 收尾说明

做完了，在 `worktree-node-status` 分支上（`94811f6`），尚未合回 main。

**标签是「已注册」，不是上面写的「在线」——这是一处有意的偏离。** 第 2 条和第 5 条
不能同时按字面成立：注册之后没有任何一处再写这一列，agent 挂掉状态也不会变，所以
「在线」这个词一定会撒谎，而这张票的全部目的就是别再让这一列撒谎。票里试图用正文重新
定义这个词（「「在线」的含义是……注册过」），但管理员看的是徽章上那两个字，不是注释——
那正是这张票要修的失败方式本身。

「已注册」回答的是管理员真正在问的那个问题：安装命令跑成了没有。上面第 2 条打勾指的
是它的实质——注册当场翻转、不用重启任何东西——已经做到。

数据库里的取值是 `unregistered` / `registered`，两侧测试都断言字面量：任一侧改名都会
让测试红，而不是让页面上每个节点静静变成「—」。

存量行的 `'8123'` 由 `sql/migrate-2026-09-05-node-status.sql` 清成 NULL，页面显示
「—」。没有一律写成 `unregistered`：那些节点里有一部分 agent 正跑着，只是从来没人记录
过，把它们说成「未注册」和继续显示 8123 一样是编造。

**曾经欠着一步，现在补上了：** `internal/model/entity/nodes.gen.go` 上还写着
`default:8123`——按 `docs/development.md` 的三步走，产物只能重新生成、不能手改，而重新
生成要一个已经执行过迁移的库。做票 04 时发现这台机器上就有跑着的 MySQL（docker，
13306），于是把迁移在开发库上执行了一遍再跑 `stander gen`，那个默认值已经从产物里消失。
