# 01: 改节点能绕过建节点的规则，还会把倍率悄悄清零

**What to build:** 建节点时立下的规则，改节点时同样成立：名字去空格后不能为空，倍率
必须大于 0。并且只改名字的那次请求，不会顺手把倍率改掉。

`fix-node-create` 02 把这些规则加在了创建路径上（服务层一个纯函数，表驱动测试）。
EditNode 没有跟上，于是一个按规则建出来的节点，改一次就能失去这些性质：名字原样存，
两端空格不裁；倍率那句判断是 `if r.Rate >= 0`，零通过。

更麻烦的是同一句判断的另一面。`EditNodeReq.Rate` 是 `float32`，请求里**不带**这个
字段时它解出来就是 0，而 0 满足 `>= 0`，于是被当成一次真实的修改写进库——**只改名字
的请求会把节点倍率清成 0**，那个节点上的流量从此不计费。这句判断唯一挡住的是负数，
它想表达的「没传就别改」一条也没做到。

控制台的编辑对话框每次都同时发 NodeName 和 Rate，所以点界面碰不到；换任何一个别的
调用方就能碰到。

**Blocked by:** None（`fix-node-create` 02 已落地，规则可直接复用）

**Status:** ready-for-agent

## 要点

零和「没传」在 `float32` 上是同一个值，这是这张票真正的难处。想同时做到「没传就别改」
和「传了 0 就拒绝」，字段得能表达「缺席」——指针是通常的答案，改动会落到请求结构体和
前端两处。挑一个做法之前先把这一点想清楚，别用一个「0 当作没传」的约定糊过去：那正是
现在这个 bug。

- [ ] 名字去空格后为空的编辑请求被拒，理由与创建时是同一句
- [ ] 倍率为零或负数的编辑请求被拒，理由与创建时是同一句
- [ ] 不带倍率的编辑请求不改倍率，也不报错
- [ ] 不带名字的编辑请求不改名字
- [ ] 名字两端的空格在编辑时也被裁剪
- [ ] 规则与创建路径共用一处实现，不是抄一遍
- [ ] 表驱动测试覆盖上面每一条（prior art：`internal/service/node_test.go` 的 `TestValidateAddNode`）

## Further Notes

`EditNodeReq.ID` 是 `json:"ID,omitempty"`，不像隔壁 `EditChainReq` 那样标 `required`。
不带 ID 的编辑请求会落到 `where id = 0`，改不到任何行也不报错。顺手一起收拾。
